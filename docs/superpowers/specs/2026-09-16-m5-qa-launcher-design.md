# M5 disposable QA launcher design

Issue: #21 (historical QA F15/F19). This specifies test support, not a new Lumen runtime path. The September 12 failures were observed manual shell, state and evidence-handling mistakes; they do not establish a product authorization defect.

## Interface and ownership

`scripts/qa/m5_launcher.ps1` is the Windows PowerShell entry and explicitly names a WSL distro. `scripts/qa/m5_launcher.sh` is the Bash entry inside WSL. Both invoke one Python 3.11+ standard-library core, `scripts/qa/m5_launcher.py`, so fixture rules do not diverge by shell. Neither wrapper performs shell guessing or imports credentials from a caller's session. The PowerShell wrapper supplies the Windows Git SHA/dirty bit because WSL Git cannot resolve this Windows-linked worktree's `.git` pointer.

Fixtures are named with a restricted slug and live only under `$HOME/.local/share/lumen-m5-qa/fixtures/<name>` on WSL's Linux filesystem. A selection file identifies the active fixture across shells. Init stages a complete fixture before atomically selecting its final name, serializes concurrent init calls, and reclaims only validated same-name interrupted stages on retry. Each fixture has an ownership marker and nonsecret JSON manifest containing a randomly generated workspace UUID, bind port, model endpoint/name, source SHA/dirty status, config/database paths, binary path/hash, and owned process PID plus Linux start time. A random bearer token is stored separately with mode 0600 and never serialized into the manifest, logs, result JSON, or URLs. Evidence is retained in a sibling directory keyed by fixture ID, outside the deletable fixture root. The root/marker and resolved paths are checked before mutations; symlink and foreign roots are refused.

## Operations

`init` creates/selects a fixture without touching other project trees. `select` changes the active fixture. `build` uses `--locked` and the stable WSL-only Cargo target from issue #24, records the exact binary hash, and reuses that hash on repeated calls if source metadata is unchanged. `start` launches that exact binary with the token and a recorded launch ID in its environment, not argv, and waits to a visible finite deadline for the authenticated cheap readiness route. If interrupted before PID persistence, a later command can recover only a process with the matching launch ID, token, binary and config. `status` reports the fixture identity, process identity and readiness without exposing the token. `stop` signals only a PID whose `/proc` start time and command still match the recorded owned process, waits for exit, and does not kill Ollama or WSL. Model readiness is separately opt-in.

`poll-job` checks an exact job UUID, revision and scheduled-for millisecond occurrence in the selected local SQLite fixture until a bounded deadline and records every observed state; a sleep expiry never counts as success. It correlates a succeeded occurrence with a completed agent run. IDs are UUIDs from server responses or the manifest, never copied from unrelated pending approvals. The launcher never grants approvals; `approval-check` inspects an exact run/action through the authenticated API and returns its scrubbed fingerprint, arguments and capabilities for the operator to compare in the normal UI. HTTP failures, malformed IDs and expired approvals are reported as failures rather than inferred successes.

`snapshot` opens an existing SQLite database read-only and uses SQLite's online backup API to write a checked, hashed copy even when the source is in WAL mode. `restore` requires a stopped owned fixture and a verified snapshot for that same fixture, uses the backup API to restore into the selected database, and retains the snapshot. Intentional tamper tests should operate on disposable clones, not on the only healthy fixture. `record` writes structured, secret-redacted command/outcome/evidence metadata and allows screenshots or sanitized response files to be attached to the evidence directory. `cleanup` is explicit and removes only the verified selected fixture; it leaves evidence and build caches intact. No command deletes, stashes, resets or edits another checkout.

## Failure and verification boundaries

Init refuses unsupported shell/platform, invalid names, a non-Linux filesystem home, missing tools, or an occupied explicit port. Start refuses absent/stale binary, changed source metadata, unowned/live PID or occupied port. Destructive operations fail closed on missing markers, symlinks, mismatched fixture IDs, malformed snapshot metadata or a still-running service. Status and polls use finite HTTP timeouts and bounded response sizes. Tests exercise fresh/repeated setup, state resume, wrong shell, malformed IDs, WAL backup/restore, symlink/foreign cleanup refusal, HTTP and polling failures, interrupted startup, and token redaction. Windows wrapper and a real WSL owned fixture are checked separately; unavailable live model/browser acceptance is reported as unrun.
